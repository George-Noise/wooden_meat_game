# Общие правила Kompot

Эта страница объясняет договорённости, которые действуют между отдельными
функциями. Точные сигнатуры находятся в [справочнике API](API.md), а готовые
модули - в [рецептах](RECIPES.md).

## Где выполняется код

| Место | Что здесь делать | Чего не переносить сюда |
|---|---|---|
| Загрузка Lua-модуля | Объявлять компоненты, внешнюю модель через `new_state`, тему и `preview` | Хуки `state/remember/effect`, построение живого дерева |
| Композиция: функция Screen/content | Читать состояние и строить элементы; вызывать хуки в постоянном порядке | Загрузку файлов, подписки и игровые действия при каждом вызове |
| Событие: `on_click`, `on_change`, drag | Проверять запрос и обновлять модель | Вызовы `UI.Button`, `K.Box`, `K.state` или `K.effect` |
| `K.effect` после применения кадра | Синхронизировать внешний код с состоянием, подписываться и возвращать очистку | Считать первоначальное `is_idle` завершённой анимацией |
| `on_dispose`/очистка эффекта | Освобождать ресурс области | Подменять запрос закрытия окна или подтверждение игрока |
| `on_size`/`on_placed` | Получать результат раскладки; обновлять модель только при отличии | Постоянно менять размер на новый, создавая цикл измерения |
| `Canvas.draw` | Рисовать в локальных пикселях переданного холста | Строить дерево UI или использовать экранные координаты как локальные |

Kompot может повторить композицию. Побочное действие, выполненное прямо в её
теле, тоже может повториться. Эффект с ключами перезапускается при их изменении,
очищается при смене ключей и удалении области. `remember` хранит результат,
но само по себе не освобождает ресурс.

## Кто владеет состоянием

Данные идут от модели к компоненту, запросы пользователя - обратно через
события. Например, `Checkbox.on_change(value)` не присваивает `checked`,
`Tabs.on_select(index)` не переключает вашу страницу, `MenuItem.on_click`
не закрывает родительское меню.

`K.state` привязан к области композиции, `K.new_state` можно создать вне её.
Чтение `.value` подписывает текущую область; `:peek()` читает без подписки.
У таблиц стандартное сравнение проверяет ссылку: изменение вложенного поля
на месте не отправит уведомление. Используйте новую таблицу, `patch` или
`update_field`. Для обычных внешних данных есть `poll`; `remember` не заменяет
наблюдение за ними.

Хуки должны выполняться в одном порядке. Условие внутри отдельного
`K.component` не должно менять набор хуков этой же области между кадрами.
Меняющееся дерево стройте отдельными компонентами и устойчивыми ключами.
`key` - идентичность, `tag` - метка для поиска, индекс - текущее положение.
При перестановке списка ключом обычно служит ID записи, а не индекс строки.

Подробности: [состояние](STATE.md), [жизненный цикл и хуки](STATE.md#время-жизни-и-диагностика-хуков).

## Что означает размер

Размеры и координаты UI заданы в пикселях области приложения. Родитель
передаёт ребёнку диапазоны допустимых ширины и высоты. `width/height/size`
выбирают размер в этих ограничениях; `required_size` нужен для намеренного
выхода за обычное согласование.

| Настройка | Смысл |
|---|---|
| `fill_max_size()` | Занять доступный конечный размер родителя, не обязательно всего экрана |
| `match_parent_size()` | Прямой ребёнок Box, измеряемый после определения размера Box; сам размер родителя не задаёт |
| `weight()` | Доля оставшегося места в Row/Column, не процент ширины экрана |
| `size_in/width_in/height_in` | Границы измерения |
| `offset()` | Сдвиг без дополнительного места в раскладке |
| `scale()/rotate()` | Преобразование рисунка и ввода; измеренный размер для соседей прежний |
| `Image.fit` | Масштабирование исходной картинки внутри уже выбранной области |
| `clip()` | Обрезка последующих слоёв и детей по форме, без выбора fit |

`fill_max_height` внутри неограниченной вертикальной прокрутки не создаёт
конечный viewport. Для прокрутки и SplitPane сначала задайте доступную область.
Пустой `Box` с единственным `match_parent_size` не получает размер из этого
ребёнка. Для фона окна размер задают контейнер и основное содержимое.

## Почему важен порядок модификаторов

`M:background(color):padding(12)` рисует фон и затем отступает внутрь него.
`M:padding(12):background(color)` оставляет внешний отступ вокруг фона.
Тот же принцип действует для рамок и текстур.

Форма `background`/`border` относится только к рисунку слоя и не обрезает
детей. `clip(shape)` обрезает следующие слои, включая ввод. Тень и рамку
обычно задают до обрезки, внутреннее содержимое - после неё.
Для фоновой картинки используйте [Image внутри Box](SKINS.md#картинка-фоном-на-весь-экран).

## Ресурсы не равны Lua-модулям

`require "pack:module"` ищет Lua-модуль пака. Строка изображения
`"atlas:sprite"` ищет спрайт атласа, а `"gui/background"` - обычную текстуру.
Kompot не подставляет имя пака в строку ресурса и не удаляет его автоматически.
Нужны подходящая запись `preload.json` и размер PNG/спрайта для contain/cover
или nine-patch. Путь к TTF тоже не является именем готового ресурса шрифта.

Цвета Kompot - `#RRGGBBAA` либо `{r,g,b,a}` с каналами 0..1.
Методы пиксельного `Canvas:set/line/rect/clear` используют каналы 0..255
или упакованный цвет движка. Параметр `Canvas:image(..., {color=...})`
использует обычный KompotColor. У HSL оттенок h задан в градусах, s/l - в 0..1.

См. [изображения и скины](SKINS.md), [шрифты](FONTS.md).

## Фокус, доступность и видимость

Обычный HUD не включает Tab по умолчанию. `keyboard_navigation=true`
в mount или preview включает общий обход; `focusable` нужен отдельному
контролу. Меню и Select имеют локальную навигацию даже без общего обхода.
Клавиатурная рамка и наведение мышью - разные состояния.

`enabled=false` запрещает пользовательские действия только у компонента,
который реализует эту опцию. Это не универсальное поведение любой таблицы props.
Например, `Card` и `ListRow` не передают её в свою область клика; для них
не передавайте соответствующий обработчик. У текстового поля
`editable=false` оставляет выделение и копирование, `enabled=false` отключает
ввод и фокус. `Select.read_only` сохраняет отображение значения без выбора.
`alpha(0)` не заменяет управление видимостью и политикой ввода.

Видимость задаёт владелец. `on_close` и `on_dismiss` - запросы, а не события
завершения удаления. Компонент с анимацией выхода остаётся в дереве во время
перехода. Для действия после группы анимаций используйте TransitionState,
`completion` и `effect`. Не удаляйте компонент условием сразу после смены цели.

См. [переходы](MOTION.md), [текстовые поля](TEXT_INPUT.md).

## Индексы, координаты и возвращаемые значения

- Lua-списки, вкладки и ячейки используют индексы от 1. Select/Choice выбирают
  значение; Tabs/Segmented выбирают индекс.
- `anchor/caret` нативного редактора начинаются с 0 и используют единицы caret
  движка, не байтовые смещения Lua-строки.
- Pointer/drag дают локальные координаты после обратного преобразования и
  отдельные parent_* координаты для изменения геометрии родителя.
- `Layout.api.place` размещает относительно собственного содержимого.
  `on_placed` сообщает координаты в приложении, `handle:is_over` принимает
  экранные координаты с учётом положения хоста.
- `scroll:fraction()`, `color.to_hsl()` и `K.args()` возвращают несколько
  отдельных значений Lua. Присваивайте `local a,b = ...`.

В VCTS доступ к TS-массиву от 0 переводится компилятором, но числовые аргументы
API остаются индексами Lua. Подробности: [VCTS](VCTS.md).

## Как выбрать тему и реализацию

`UI.theme(opts)` создаёт самостоятельную тему. `UI.Theme(opts, content)`
наследует ближайшую текущую тему Kompot UI для поддерева. `K.Theme(theme, content)`
предоставляет уже готовую таблицу без построения токенов встроенной системы.

`UI.Button` вызывает встроенную реализацию. `K.ui().Button` берёт реализацию
из текущего `theme.ui`; базовая тема ядра такого контракта не имеет.
Переопределение `UI.theme({ui=...})` относится к `K.ui()`, а не подменяет
прямой `UI.Button`. Для смены рисунка готовых контролов обычно нужны
`surfaces/shapes/colors/metrics`, для другой дизайн-системы - свой контракт.

Таблицы props в Lua не реализуют наследование поведения. Window использует
Panel внутри, но не пересылает все её свойства. Dialog использует Window,
но фиксирует центр, модальность и слой. Поэтому перенос параметра по сходству
имён не гарантирует результат; ограничения есть в [карточках API](API_UI.md).

## Что проверить в игре

Lens выполняет Lua и помогает проверить композицию, раскладку и анимации.
Он не заменяет нативный textbox: выделение, историю ввода, системные клавиши
и presentation проверяйте в совместимой сборке VoxelCore. Повороты и фигурная
обрезка нативного поля имеют отдельные ограничения. Слой с преобразованием
или фигурной маской ограничен 2048 пикселями по оси.

Галерея F12 показывает живые примеры, а справочник API описывает контракт.
Ни типы, ни пример не обещают, что неизвестный параметр обычной Lua-таблицы
будет проверен: многие лишние поля могут быть проигнорированы.
